At run start, every in-party character contributes its weaponPool to the level-up draft pool, and every in-party character's passive is applied — all inside the DETERMINISTIC sim (pure). STEP 1 — PURE SIM HELPERS in src/sim/data/characters.ts
Add (do not remove existing exports):

  export interface PartySelection { leader: CharacterId; supports: CharacterId[]; }

  // The full set of in-party members (leader first, then supports), deduped, order-stable.
  export function partyMembers(p: PartySelection): CharacterId[] {
    const out: CharacterId[] = [p.leader];
    for (const s of p.supports) if (s !== p.leader && !out.includes(s)) out.push(s);
    return out;
  }

  // Union of every in-party character's weaponPool, deduped, order-stable (leader's pool first).
  export function partyWeaponPool(p: PartySelection): string[] {
    const out: string[] = [];
    for (const id of partyMembers(p)) for (const w of CHARACTERS[id].weaponPool) if (!out.includes(w)) out.push(w);
    return out;
  }

  // Aggregate passive multipliers/additions to apply to a fresh player at run start.
  // Deterministic, pure. Interpret each in-party character's passive by its id:
  //   'determination' -> maxHp *= (1 + perLevel * trainingLevel)   (health)
  //   'weapon_mastery' -> damageMult *= (1 + perLevel * trainingLevel) (damage)
  //   'magnet'        -> magnetMult *= (1 + perLevel * trainingLevel) (pickup range)
  // trainingLevel defaults to 1 (outside-adventure upgrading of training levels is OUT OF SCOPE here; pass 1).
  // Return a plain struct the caller applies; do NOT mutate anything here.
  export interface PartyPassives { hpMult: number; damageMult: number; magnetMult: number; }
  export function partyPassives(p: PartySelection, trainingLevel = 1): PartyPassives { ... }

Implement partyPassives by starting from {hpMult:1, damageMult:1, magnetMult:1} and, for each member, switching on member.passive.id to multiply the matching field by (1 + passive.perLevel * trainingLevel). Unknown passive ids are ignored (no-op). Keep it pure.

STEP 2 — APPLY PARTY AT RUN START (deterministic)
The existing loadout is applied in main.ts startRun() (render/host layer) which sets st.player.weapons/maxHp/hp/speed from the leader's CharacterDef (per char_roster_gdd.txt). Extend the run-start path so party passives + pool are applied deterministically. Two acceptable wiring options — pick ONE and state which:
  (A) SIM-SIDE (preferred, keeps determinism obvious): add an exported pure function in sim, e.g. in src/sim/data/characters.ts or a thin new sim helper, `applyPartyToPlayer(player, party, trainingLevel=1)` that multiplies player.maxHp by hpMult (and sets player.hp = player.maxHp), player.attackDamage by damageMult, player.magnetRadius by magnetMult. Also expose the draft pool as data the upgrade system can read (see STEP 3). Call this from startRun() right after the leader loadout is set. Because it only reads the party + defs and mutates the passed-in player, it is deterministic.
  (B) HOST-SIDE: compute PartyPassives in startRun() via partyPassives(party) and apply the same multiplications inline. Still deterministic since it's pure math over static data.
Either way: read 'rs_party' in startRun() (default {leader: rs_selected_character||'explorer', supports:[]}), and apply. State clearly in a comment that this runs once at run start and uses no wall-clock/random.
NOTE the ordering: leader base stats (maxHp/speed/default weapon) are set first (from char_roster_gdd.txt), THEN party passive multipliers are applied on top. Set player.hp = player.maxHp AFTER the hp multiplier so the player starts at full.
