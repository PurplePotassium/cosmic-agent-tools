GOAL: Add an on-screen virtual joystick VISUAL for the existing touch/mouse-drag movement. Realm Survivors is a vertical mobile game: press finger + drag moves the character in that direction; release stops. The movement math already works (src/render/input.ts InputManager.readInput produces a normalized {dx,dy} from a drag) and is already fed to the sim in src/main.ts. This spec ONLY adds the joystick graphic that shows the base at the touch point and a knob that follows the finger. Do NOT change the move vector the sim receives, and do NOT touch any sim file.

HARD RULES (must hold): NEVER edit game/test/** or game/accept/**. src/render/** is render-only and MAY use performance.now and navigator APIs, but MUST NOT be imported by src/sim/**. Do not add Math.random. Keep the gate green (npm run gate / the project's build+test). Placeholder art is acceptable — getTexture(key) returns a labeled grey box immediately and swaps in real art asynchronously, so just use the keys.

AVAILABLE ASSET KEYS (already Ready-seeded; call getTexture with them exactly): ui.joystick_base (96x96), ui.joystick_knob (48x48). Note: these keys may not yet be present in assets/manifest.json — that is fine, getTexture(key) auto-declares a placeholder for unknown keys and never throws. Use them directly.

CURRENT STATE TO GROUND ON:
- src/render/input.ts InputManager: fields startX/startY (pointer-down point, clientX/clientY), currentX/currentY (latest drag point), isDragging, deadzone=8, activePointerId. readInput(active) returns keyboard first, else the drag vector (dx/dy)/dist when dist>deadzone. Movement is pointer-based on the whole window.
- src/render/stage.ts Renderer: a Pixi v8 Application with a world Container (camera-translated to center the player) and an app.stage. HUD overlay lives above the world. The camera sets this.world.x/y each sync(). getTexture/getEntry imported from ../assets/registry.

IMPLEMENTATION:
1. In src/render/input.ts, expose read-only accessors so the renderer can draw the joystick without duplicating pointer state. Add public getters (or a single public method) that return: whether a touch/mouse drag is currently active (isDragging AND the vector exceeds deadzone is NOT required for showing the base — show the base as soon as isDragging is true), the SCREEN-space anchor point (startX, startY in clientX/clientY pixels), and the current drag point (currentX, currentY). Example public API to add: `get dragActive(): boolean { return this.isDragging; }`, `get dragStart(): {x:number,y:number} { return { x: this.startX, y: this.startY }; }`, `get dragCurrent(): {x:number,y:number} { return { x: this.currentX, y: this.currentY }; }`. Do NOT change onPointerDown/Move/Up or readInput math — only add getters. The joystick must NOT interfere with WASD: WASD still works because readInput checks keyboard first; the joystick visual is only shown while a pointer drag is active.
2. In src/render/stage.ts, add a SCREEN-SPACE (NOT world-space) joystick overlay so it does not scroll with the camera. Add two Sprites: a base sprite from getTexture('ui.joystick_base') (96x96, anchor 0.5,0.5) and a knob sprite from getTexture('ui.joystick_knob') (48x48, anchor 0.5,0.5). Add them to app.stage (the same layer as the HUD/overlay, ABOVE this.world) so their coordinates are raw screen pixels, not camera-translated. Start both invisible.
3. Give the Renderer a way to receive the input state. Simplest: add a method `syncJoystick(input: { dragActive: boolean; dragStart: {x:number;y:number}; dragCurrent: {x:number;y:number} }): void` on Renderer, and call it from src/main.ts each frame right after computing input (in the ticker, near where inputManager.readInput is used). Pass the InputManager's new getters. In syncJoystick: if !dragActive, set base.visible=false and knob.visible=false and return. Otherwise set base.visible=true, base.x=dragStart.x, base.y=dragStart.y. Compute the knob offset = (dragCurrent - dragStart); clamp its length to a KNOB_RADIUS (use 48, i.e. half the 96 base). If length>KNOB_RADIUS scale the offset to KNOB_RADIUS. Set knob.visible=true, knob.x = dragStart.x + clampedOffsetX, knob.y = dragStart.y + clampedOffsetY. Re-pull getTexture('ui.joystick_base')/('ui.joystick_knob') each call and reassign sprite.texture only if it changed (mirror the placeholder→real async-swap pattern already used elsewhere in stage.ts, e.g. `if (spr.texture !== tex) spr.texture = tex;`), and re-set width/height=96/96 and 48/48 respectively so the async real art keeps the intended size.
4. IMPORTANT — the base+knob offset MUST match the SAME direction/magnitude convention the sim already uses: the drag vector fed to the sim is (currentX-startX, currentY-startY) normalized. The knob offset uses the same (current-start) delta (just clamped for display), so the knob visually points where the character moves. Do not invert Y. Do not recompute movement here — the sim vector still comes only from InputManager.readInput in main.ts.
5. Hide the joystick whenever movement input is not active (release → onPointerUp sets isDragging=false → dragActive false → hidden). Also ensure it stays hidden on menus: main.ts already gates stepping behind menu/levelup visibility; only call syncJoystick with a live drag during actual play, or simply rely on dragActive being false when inputManager.cancelDrag() has run (it is called on menus/level-up). Calling syncJoystick unconditionally is fine because dragActive will be false when not dragging.
