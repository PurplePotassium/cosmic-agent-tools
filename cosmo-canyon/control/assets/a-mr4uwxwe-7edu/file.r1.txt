GOAL
Add a new render-layer screen `WhoAreYouUI` (src/render/whoareyou.ts) shown on the player's FIRST Play — i.e. when no character has been chosen yet (localStorage 'rs_selected_character' is unset). It lets the new player choose a male or female Explorer appearance, records it, and proceeds into the normal flow. On every subsequent Play it is skipped.

HARD RULES (state and obey):
- NEVER edit game/test/** or game/accept/** (tamper guard reverts+blocks). 
- This is a src/render/** screen: performance.now is allowed for animation; do NOT import from src/sim/** except pure data (you may import from src/sim/data/characters if convenient, but it is not required). Do NOT put any game logic in sim.
- Keep the gate green (`npm run -s typecheck` + tests). Run them.
- Game must never break on missing art: getTexture(key) returns a grey-box placeholder synchronously and swaps in real art async. A Sprite must reassign `.texture = getTexture(key)` every frame in sync() to adopt real art once it loads (mirror how charselect.ts refreshes its background/char sprites).

PRE-FACT (verified): texture keys panel.whoareyou, player.explorer_m, player.explorer_f are NOT yet in game/assets/manifest.json. That is fine — getTexture auto-declares unknown keys as placeholders. Reference them by key; do not edit the manifest, do not block on them.

STEP 1 — CREATE src/render/whoareyou.ts
Model the class after CharSelectUI / SettingsUI structure (constructor builds a `readonly root = new Container()`; `init(app, onDone)`; `show()`; `hide()`; `sync(screenW, screenH)`; a keydown handler installed in init and gated on `this.root.visible`). Specifics:
- Background: a Sprite whose texture is refreshed each frame to getTexture('panel.whoareyou'); stretch to screenW x screenH (anchor 0). Add a translucent dark overlay Graphics on top for legibility (match charselect's 0x070714 @ ~0.5 alpha pattern).
- Title Text near top, centered: 'WHO ARE YOU?' (monospace, gold #f5d76e, bold, ~28px, matching charselect title style).
- Two large choice tiles side by side, centered vertically: LEFT = Male Explorer, RIGHT = Female Explorer. Each tile = a Container holding: a Sprite (texture refreshed each frame to getTexture('player.explorer_m') for male, getTexture('player.explorer_f') for female; scale ~2.6 like charselect), a caption Text below it ('MALE' / 'FEMALE', or 'EXPLORER (M)' / 'EXPLORER (F)'), and a subtle framed background Graphics. Make each tile interactive (interactive=true, cursor='pointer') with pointerover/pointerout hover feedback (scale bump or tint) mirroring charselect.
- Selection on click: define `_choose(gender: 'male'|'female')` that:
    localStorage.setItem('rs_explorer_gender', gender);
    localStorage.setItem('rs_selected_character', 'explorer');
    // ensure the unlock set exists with explorer
    if (!localStorage.getItem('rs_unlocked_characters')) localStorage.setItem('rs_unlocked_characters', JSON.stringify(['explorer']));
    this.hide();
    if (this._onDone) this._onDone();
  IMPORTANT: call this.hide() BEFORE invoking the onDone callback (this mirrors the CharSelect §AUDIT-2026-07-02 CRIT-8 fix — leaving root.visible true would block the next screen's sim-step/render and can soft-lock the flow).
- Keyboard: ArrowLeft/ArrowRight moves a highlight between the two tiles; Enter confirms the highlighted one via _choose; default highlight = male (left). Draw the highlight as a gold stroke around the active tile (mirror charselect _applyHighlights).
- sync(screenW, screenH): reposition/scale background, overlay, title, and the two tiles responsively (center the pair with a horizontal spread like charselect's hSpread). Return early if `!this.root.visible`.
- Remove the keydown listener is not required (charselect keeps its listener installed and gates on visibility — do the same).
