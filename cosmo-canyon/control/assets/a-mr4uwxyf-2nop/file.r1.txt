ARCHITECTURE — CENTRALIZE PLAYER DAMAGE (do this first): Add an exported deterministic helper `applyPlayerDamage(s: GameState, amount: number, opts?: { source?: 'contact' | 'telegraph' | 'projectile' }): void` (put it in src/sim/systems/combat.ts and export it; import where needed). This helper is the single choke point where reactive weapons intercept damage. Its logic:
  1. If amount <= 0 or !s.player.alive, return.
  2. TOWER SHIELD: if the player has an equipped weapon with weaponId 'tower-shield' AND its reactive cooldown is 0 (ready): NEGATE this damage entirely (do NOT subtract from hp), start the shield cooldown (45s), and TRIGGER the shield effect (see below). Return WITHOUT applying damage. (Shield negates exactly ONE hit, then goes on cooldown for 45s.)
  3. SMOKE BOMB: if the player has 'smoke-bomb' equipped AND its cooldown is 0 (ready): this does NOT negate the triggering damage by default (GDD says brief invincibility + AoE damage). Apply the triggering damage normally (step 4) BUT then start a short INVULN window and the 30s cooldown and trigger the smoke AoE. During the invuln window, applyPlayerDamage should return early (negate) for its duration. (So smoke-bomb reduces incoming damage during the brief window after a hit, and damages nearby enemies.)
  4. Otherwise subtract: s.player.hp -= amount; if s.player.hp <= 0 { hp = 0; alive = false; outcome = 'loss' }.
Then REPLACE the direct `p.hp -= ...` writes at the three damage sites with calls to applyPlayerDamage(s, dmgAmount, {source}): (a) in combatSystem, the contact-damage line becomes applyPlayerDamage(s, dps * FIXED_DT, {source:'contact'}); (b) in loop.ts telegraph pass, `p.hp -= t.damage` becomes applyPlayerDamage(s, t.damage, {source:'telegraph'}); (c) in boss-attack.ts if it deducts player hp, route it through applyPlayerDamage(...,{source:'projectile'}). IMPORTANT: keep the EXACT same numeric result for the default loadout (no shield/smoke) — applyPlayerDamage's step 4 must reproduce the current behavior byte-for-byte (same subtraction, same <=0 -> alive=false/outcome='loss'), so determinism.ts and win-loss.ts stay green. Contact damage is a per-tick fraction (dps*FIXED_DT); note that routing tiny fractional hits through the shield would waste the negate on a 0.13-hp tick. To make the shield meaningful, ONLY treat a hit as a 'shield-worthy hit' when source is 'telegraph' or 'projectile' (discrete burst hits), OR when amount >= a threshold (e.g. >= 5). For 'contact' fractional damage below the threshold, skip the shield/smoke trigger and just apply normally. Document this threshold in a comment. (This keeps determinism intact and matches the GDD intent of negating a real hit, not a sliver of contact damage.)
