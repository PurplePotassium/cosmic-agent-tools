ADD THESE FOUR WEAPONS (WeaponDef in WEAPON_POOL + behavior branch in weaponSystem + render in stage.ts):

1. WHIP — id 'whip', name 'Whip', rarity 'common'. GDD: ALTERNATES between (a) a long-range OVAL attack toward the nearest enemy and (b) a SWEEP AoE slightly larger than Greatsword. Deterministic alternation: store a per-slot alternation counter. The EquippedWeapon interface (src/sim/state.ts) has {weaponId,level,timer,rarity?}. Add an OPTIONAL field `altCount?: number` to EquippedWeapon (defaults undefined -> treat as 0). Add a new WeaponBehavior 'whip'. In the branch: read n = slot.altCount ?? 0; if n is even => do the long-range oval attack toward nearest (an instant AoE over an OVAL region: approximate an oval by an ellipse test — damage enemies where ((ex/ax)^2 + (ey/ay)^2) <= 1 with center at player+(nx,ny)*offset, ax the long axis ~120 along the (nx,ny) direction, ay the short axis ~50; to keep it simple and deterministic you MAY approximate the oval as a circle of radius ~90 at player+(nx,ny)*90 if an ellipse rotated to the aim direction is too fiddly — a rotated ellipse is preferred but a circle is acceptable). If n is odd => do a SWEEP AoE centered near the player (like Greatsword's sweep-front but radius slightly LARGER, ~100px, centered at player+(nx,ny)*40). Both variants: collect-then-kill enemies + hit destructibles, increment s.weaponAoeFires. After firing, set slot.altCount = n + 1. This alternation is fully deterministic (no rng). cooldown ~1.1, baseDamage ~40.

2. THROWING HAMMER — id 'throwing-hammer', name 'Throwing Hammer', rarity 'common'. GDD: thrown UPWARD in an arc that FALLS to the bottom of the screen (a parabola). Deterministic parabola: this is a projectile with GRAVITY. Add OPTIONAL field `gravity?: number` to the Projectile interface (px/s^2 downward). Add a spawnArcingProj helper (or extend spawn) that sets an initial upward velocity (vy negative, e.g. vy = -300) plus some horizontal velocity toward nearest (vx = nx * 150) and proj.gravity = a positive constant (e.g. 600). Add a new WeaponBehavior 'arc'. Its branch spawns ONE arcing projectile. In the projectile MOVE loop (weaponSystem), when proj.gravity is set/positive, apply `proj.vy += proj.gravity * FIXED_DT` each tick BEFORE moving (so it rises then falls). The hammer damages enemies on contact like a normal projectile (reuse the existing hit path) and despawns at maxRange or when it exits the arena / reaches a bottom bound (you may despawn on maxRange as the existing loop does). Because gravity accumulates on vy, the path is a deterministic parabola. Ensure gravity is reset (to undefined/0) for non-arc spawns so a reused pool slot does not keep falling. cooldown ~1.4, baseDamage ~55 (heavy).

3. FLAIL — id 'flail', name 'Flail', rarity 'common'. GDD: a rotating spiky ball ORBITING the character, dealing CONSTANT contact damage each tick to enemies it touches. This is NOT a projectile — it is a persistent orbiting hitbox. Deterministic orbit driven by sim TIME (s.time), not wall clock. Model it as sim state on the player or GameState: since the flail exists only while equipped, drive its position from s.time and the slot: add a new WeaponBehavior 'orbit'. Implementation approach (deterministic, no rng, no per-tick allocation): in weaponSystem, AFTER the slot-firing loop (or in a dedicated pass), for each equipped 'orbit' weapon compute the ball's world position from an angle = s.time * ORBIT_ANGULAR_SPEED (e.g. 3.0 rad/s) and radius ~70px around the player: bx = player.x + cos(angle)*70, by = player.y + sin(angle)*70. Then damage every enemy within (ballRadius ~20 + enemy.radius) of (bx,by) THIS tick: apply damageForLevel(def, level) * FIXED_DT as a per-tick contact tick (so damage-per-second is roughly baseDamage), collect-then-kill, and count these AoE-style hits toward s.weaponAoeFires if you want the AoE counter to reflect it (optional). Because the flail applies damage every tick while overlapping, use a per-tick fractional damage (baseDamage scaled by FIXED_DT) rather than full baseDamage per tick, so it reads as a continuous contact weapon. To support MULTIPLE flails or duplicate slots, offset each additional flail's angle by (PI * slotIndexAmongFlails) so they orbit opposite each other — deterministic. Note: because the flail's cooldown-timer firing model does not fit (it is continuous), you may either (a) keep a nominal cooldown in the WeaponDef but IGNORE it for orbit (drive purely from s.time), or (b) fire the orbit tick every frame from a separate loop over orbit-weapons — approach (b) is cleaner. Keep the WeaponDef.cooldown at a nominal value (~1.0) for schema consistency even if unused by the orbit path. baseDamage ~120 (this is DPS-per-second before the FIXED_DT scaling). Ensure this continuous path stays deterministic: angle from s.time only, enemy iteration via forEachActive (ordered).

4. ACID POTION — id 'acid-potion', name 'Acid Potion', rarity 'common'. GDD: thrown RANDOMLY near a RANDOM enemy; creates a TEMPORARY ground AoE PUDDLE that ticks damage for a duration. This is the ONE weapon that legitimately uses rng — and it MUST use state.rng, never Math.random. Add a new persistent sim structure for puddles: define `interface AcidPuddle { id:number; x:number; y:number; radius:number; remaining:number; dps:number }` in src/sim/state.ts and add `acidPuddles: AcidPuddle[]` to GameState, initialized to [] in newGame(). Add a new WeaponBehavior 'acid-throw'. Its branch: pick a RANDOM active enemy using state.rng (e.g. count active enemies, r = s.rng.int(0, count), select the r-th in forEachActive order — deterministic given the seed), then place a puddle near that enemy at an rng-jittered offset: px = enemy.x + s.rng.range(-30, 30), py = enemy.y + s.rng.range(-30, 30); push { id: s.nextId++, x:px, y:py, radius ~70, remaining ~3.0 (seconds), dps = damageForLevel(def, level) } onto s.acidPuddles. If there are no active enemies, do nothing (skip, reset timer to fire next tick as the existing !hasTarget guard does — note: acid needs a target too, so the existing hasTarget guard is fine). Add a puddle-tick pass in weaponSystem (or a small helper called from it): for each puddle, remaining -= FIXED_DT; damage every enemy within radius by dps * FIXED_DT (per-tick fraction), collect-then-kill; also damage destructibles similarly; increment s.weaponAoeFires when a puddle deals damage (optional but lets AoE tests observe it). Remove puddles whose remaining <= 0 (filter the array once after the pass, like telegraphs are filtered in loop.ts). All rng calls MUST be s.rng.* — this keeps determinism (same seed => same puddle placement). cooldown ~2.2, baseDamage ~30 (as puddle dps).
